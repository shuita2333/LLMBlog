DPO 直接偏好优化详解：不用奖励模型，也能让模型学会偏好

发表于2026-08-27|更新于2026-08-27|模型训练

经典 RLHF 的链路很长：先训练奖励模型，再让语言模型在线生成回答，最后用 PPO 优化奖励。DPO 问了一个很聪明的问题：既然最终目标只是让优选回答比拒绝回答更可能出现，能不能直接在偏好对上训练语言模型？

答案是可以。DPO 全称 Direct Preference Optimization，由 2023 年的论文《Direct Preference Optimization: Your Language Model is Secretly a Reward Model》提出。它把带 KL 约束的 RLHF 目标改写成一个类似二分类的损失，不需要显式奖励模型、Critic，也不需要训练时在线 rollout。

为什么一定要减去参考模型

只优化 也能做排序，为什么还需要 ？

因为参考模型提供了一个锚点。假设 chosen 本来就是一句极其罕见、语法奇怪的话，单纯拉高它可能破坏语言能力。DPO 比较的是“相对于原模型改变了多少”，它来自原始 RLHF 目标中的 KL 正则，而不是随手加上的技巧。

不过，参考模型并不保证当前策略在每个位置都接近参考策略。DPO 是从最优策略关系推导出的离线目标，不等价于在训练过程中显式监控一个固定 KL 上限。

β 到底越大约束越强，还是越弱

这是 DPO 教程中最容易产生口径混乱的地方。

在原始 RLHF 目标里， 是 KL 惩罚系数，越大表示理论上的最优策略越靠近参考模型。但在 DPO 损失中， 同时缩放分类 logit，直接影响梯度和训练动态。因此不能只凭某一次训练里“ 调大后模型变化更大/更小”来解释理论含义。

稳妥的理解是： 决定偏好间隔的尺度，并继承了奖励与参考约束之间的权衡。实际选择需要结合数据噪声、学习率、序列长度处理和验证集调参。

DPO 实际如何计算序列概率

回答概率是每个 token 条件概率的乘积，对数以后变成求和：

训练时通常要对同一批 chosen 和 rejected 分别计算：

  • 当前策略的序列 log-prob；
  • 冻结参考策略的序列 log-prob。

参考 log-prob 可以提前缓存，也可以在训练中前向计算。使用 LoRA 时，还可以暂时关闭 adapter，让同一个基础模型充当参考模型，从而节省显存，但必须确认实现语义正确。

序列概率天然随长度累加。长回答有更多负 log-prob 项，也更容易产生长度偏差。是否按 token 平均、怎样截断、chosen 是否普遍更长，都会影响训练结果。

一次完整的 DPO 训练

  1. 准备一个已经会遵循指令的 SFT 模型；
  2. 对每个 prompt 收集多个候选回答；
  3. 由人工、AI Judge 或规则选出 chosen 与 rejected；
  4. 冻结一份 SFT 模型作为 ；
  5. 计算两模型对 chosen/rejected 的 log-prob；
  6. 最小化 DPO loss，更新 ；
  7. 监控隐式 reward margin、长度、KL 代理指标和真实评测结果。

DPO 是 offline 方法：训练样本通常是事先收集好的。它不要求训练中的当前模型重新探索，因此工程上很像普通的成对分类微调。

DPO 与 SFT、PPO 的区别

方法 数据 训练信号 是否在线生成 额外模型
SFT prompt + 标准回答 逐 token 模仿 否 无
DPO prompt + chosen + rejected 相对偏好 否 冻结参考模型
PPO-RLHF prompt + 奖励 在线策略梯度 是 参考、奖励、Critic

SFT 告诉模型“请像这个答案一样写”；DPO 告诉模型“A 比 B 更好”；PPO 则让模型自己探索，只要最终奖励更高即可。

DPO 不是没有代价的万能简化

  • 依赖离线数据覆盖：当前模型可能走到数据集从未出现的区域；
  • 偏好噪声会被直接学习：Judge 偏爱长回答，模型就可能越来越啰嗦；
  • 只有相对质量，不保证绝对质量：两个回答都很差，chosen 也只是“没那么差”；
  • 概率可能一起下降：DPO 主要关心 chosen 与 rejected 的相对间隔，不天然保证 chosen 的绝对似然上升；
  • 缺少在线探索：模型不会因为训练发现了一条新解法，就自动把新轨迹加入数据。

这也是 IPO、KTO、ORPO、SimPO、在线 DPO 等后续方法不断出现的原因。

用一句话总结

DPO 就是：把“相对参考模型的概率变化”当作隐式奖励，再用 Bradley–Terry 二分类损失，让 chosen 的隐式奖励超过 rejected。

它保留了 KL 正则化 RLHF 的核心结构，却把“奖励模型 + PPO”压缩成了一次离线偏好训练。
