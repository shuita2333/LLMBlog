GRPO 组相对策略优化详解：不用 Critic，模型怎样判断谁答得更好

发表于2026-08-27|更新于2026-08-27|模型训练

PPO 需要一个 Critic 回答：“走到当前状态，正常情况下能拿多少分？”对于几十亿参数的语言模型，再养一个价值模型既耗显存，又增加训练难度。

GRPO 的想法很接地气：既然不知道一道题正常该得多少分，那就让模型对同一道题答好几遍，互相比较。 比同组平均分高的回答得到正优势，比平均分低的回答得到负优势。

GRPO 全称 Group Relative Policy Optimization，由 2024 年的 DeepSeekMath 提出，后来用于 DeepSeek-R1 等推理模型的强化学习阶段。

先用考试排名理解 GRPO

假设模型对同一道数学题生成 4 个答案，验证器给分如下：

组内平均分是 0.5。A、B 高于平均水平，应该提高概率；C、D 低于平均水平，应该降低概率。GRPO 不需要额外模型预测“这道题的基准分”，因为同一道题的其他回答就是基准。

这也是 Group Relative 的含义：优势是相对于同组样本计算的。

  • ：回答优于同组平均水平；

如果一组回答全部正确或全部错误，组内方差接近 0，优势也几乎消失。这意味着 GRPO 最喜欢“有的会、有的不会”的问题：太简单或太难的 prompt 都提供不了多少学习信号。

标准差归一化能稳定不同奖励尺度，但也会带来题目难度偏差。例如，两个回答只差一点点，在低方差组中也可能被放大。后续实现因此提供了不除标准差、使用全 batch 标准差等变体。

为什么不需要 Critic

PPO 的 Critic 学习 ，使用 构造低方差优势。GRPO 则用同一 prompt 下其他回答的平均奖励作为 baseline：

这样省掉一个与语言模型规模相近的价值模型，也省掉价值损失训练和对应的调参。但它不是“免费午餐”：每个问题必须生成多个回答，rollout 数量增加；组内回答太相似时，也没有有效比较信号。

最关键的局限：整段回答共用一个优势

如果奖励只检查最终答案，那么回答中的每个 token 通常共享同一个 。

一个 2000 token 的推理过程最后算对了，GRPO 会整体提高这条轨迹的概率。但其中可能有 500 token 是绕路、猜测甚至错误推导，只是最后碰巧修正了。反过来，一条思路很好但最后算错一个符号的轨迹，所有 token 都可能收到负信号。

这叫 credit assignment，即信用分配问题：模型知道“整张卷子得了多少分”，却不知道具体哪一步值得表扬。过程奖励模型、步骤验证器和更细粒度奖励都在尝试解决它。

一轮 GRPO 实际怎样运行

  1. 取一批 prompt，每个 prompt 复制 份；
  2. 使用当前/旧策略并行生成 个回答；
  3. 调用规则、测试用例或奖励模型计算每个回答的奖励；
  4. 在每个 prompt 的组内计算均值、标准差和优势；
  5. 计算旧策略概率比、参考模型 KL 和裁剪目标；
  6. 更新策略若干步，然后重新生成 on-policy 数据。

它最适合奖励便宜、可靠且可自动验证的任务。数学最终答案、代码单元测试和结构化输出都比开放式写作更容易提供稳定奖励。

PPO、GRPO 到底差在哪里

对比项 PPO GRPO
baseline Critic 预测状态价值 同题多回答的组内均值
是否训练价值模型 是 否
每个 prompt 的采样 可以较少 通常需要一组回答
优势粒度 可借助 GAE 做 token/状态级估计 原始形式通常是序列级优势广播到 token
主要代价 价值模型显存和训练复杂度 多回答生成成本

GRPO 不是“比 PPO 更高级”的普遍替代品，而是在 LLM 推理训练中做出的具体工程权衡。

用一句话总结

GRPO 就是：同一道题多答几遍，用组内排名代替 Critic 估计 baseline，再用 PPO 式裁剪和参考 KL 稳定更新。

它省掉了价值模型，却没有省掉奖励设计、在线采样和信用分配问题。
