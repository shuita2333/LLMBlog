SFT 监督微调详解：大模型是怎样学会回答问题的

发表于2026-08-27|更新于2026-08-27|模型训练

如果把预训练模型比作一个“读过很多书，但不知道该怎么和人聊天的人”，那么 SFT 做的事情，就是拿出一批标准示范告诉它：遇到这种问题，应该像这样回答。

SFT 的全称是 Supervised Fine-Tuning，即监督微调。它可能是后训练中最朴素的方法，但几乎所有聊天模型都绕不开它。后面的 PPO、GRPO、DPO 和 OPD 虽然目标不同，也常常从一个 SFT 模型开始。

如果不做掩码，模型也会花力气复述 system 和 user 文本。某些继续预训练式微调会对整段文本计算损失，但常规对话 SFT 更关心模型回答，因此通常只训练 completion 部分。

多轮对话还有两种常见选择：只训练最后一轮 assistant，或者训练所有 assistant 轮次。两者没有绝对对错，但必须与数据模板和训练代码保持一致。

Teacher Forcing：训练时有人把正确答案递到手边

注意前面的条件是 ，即标准答案的真实前缀，而不是模型刚刚自己生成的前缀。这种训练方式叫 Teacher Forcing。

它的好处是高效：一段回答的所有位置可以并行计算损失。问题是训练与推理存在差异：

  • 训练时，第 20 个 token 前面永远是标准答案；
  • 推理时，如果第 5 个 token 已经生成错了，后面面对的就是一个训练集中少见的错误前缀。

这通常被称为 exposure bias。SFT 只在固定数据分布上学习，也是后来在线强化学习和 OPD 强调“让模型在自己走到的状态上学习”的原因之一。

一次完整的 SFT 是怎么做的

整个流程并不神秘：

  1. 收集人工回答、业务数据或教师模型生成的高质量示范；
  2. 清洗重复、错误、格式异常和相互冲突的样本；
  3. 使用统一 chat template 拼接 system、user 和 assistant；
  4. 分词并建立 label mask，只让目标回答产生损失；
  5. 从基础模型加载权重，用全参数、LoRA 或 QLoRA 优化交叉熵；
  6. 在独立验证集上检查任务能力、格式遵循和通用能力是否退化。

这里要再强调一次：LoRA/QLoRA 决定“更新哪些参数”，SFT 决定“优化什么损失”。因此“LoRA 和 SFT 选哪个”本身是一个错误问题，完全可以使用 LoRA 来执行 SFT。

SFT 到底学到了什么

SFT 最擅长三类事情：

  • 激活已有能力：基础模型可能已经会翻译和写代码，只是不知道用户想让它做什么；
  • 学习输出协议：例如 JSON、工具调用格式、角色语气和拒答模板；
  • 注入任务示范：让模型模仿解题步骤、客服流程或特定写作风格。

但“往模型里灌大量新知识”并不总是 SFT 的强项。若目标是吸收一个专业领域的大规模文本知识，继续预训练通常更自然；若目标是区分多个都能接受的回答哪个更好，偏好优化通常更合适。

三个容易踩的坑

1. 损失下降，不等于回答更好

交叉熵衡量模型对标准答案的拟合程度。训练数据如果存在错误、模板单一或回答冗长，模型可能把这些问题学得非常好。最终仍要用任务指标和人工评测判断质量。

2. 数据质量往往比数据量更重要

一批冲突样本会让模型不知道到底应该简洁还是详细、拒绝还是回答。高质量、覆盖合理的数据常常比简单堆量更有效。

3. 一个问题可能有许多正确答案

SFT 会把数据中的一个回答当作目标。对于开放式写作，其他合理表达没有得到正向信号，甚至会因为概率归一化而被间接压低。DPO 等偏好方法不要求唯一标准答案，而是学习回答之间的相对优劣。

用一句话总结

SFT 就是：在标准答案的正确前缀上，逐 token 提高标准答案的概率。

它简单、稳定、数据利用效率高，是把基础模型变成指令模型的第一步；它的局限也来自同一个地方——模型只会模仿数据给出的行为，不会主动探索数据之外更好的回答。
