OPD 在线策略蒸馏详解：让学生在自己走过的路上请教老师

发表于2026-08-27|更新于2026-08-27|模型训练

本文中的 OPD 指 On-Policy Distillation，即在线策略蒸馏。不同领域还存在其他同名缩写，阅读论文时应先确认全称。

SFT 像是老师提前写好一批标准答案，学生回家照着练；强化学习像是学生独立答题，最后只看总分；OPD 则介于两者之间：学生先按自己的思路往下写，老师站在学生当前写到的位置，告诉它下一步各个选项有多合理。

这使 OPD 同时拥有两个特点：

  • 数据状态来自当前学生，因此是 on-policy；
  • 监督来自教师的完整 token 分布，因此比最终 0/1 奖励更密集。

Qwen3 在小模型的强到弱蒸馏中采用了“离线蒸馏 + on-policy distillation”的两阶段路线。到 2026 年，OPD 已成为推理模型和智能体后训练中的活跃方向。

OPD 与 SFT 最大的差别不是“有没有老师”

教师生成数据后做 SFT，也可以说“有老师”。真正的差别在于训练状态来自哪里：

如果学生在自己的推理中犯了一个特有错误，OPD 会让教师在这个错误前缀上继续给出分布，因此监督更贴近学生真正需要修正的位置。

但教师也不总能“救回来”。如果前缀已经荒谬到无可挽回，教师在这个局部状态上可能只能选择“最不坏的下一词”，无法告诉学生应该回到十步以前。这是局部 token 监督的边界。

OPD 与 GRPO 的差别

两者都让学生 on-policy 生成回答，但反馈完全不同：

对比项 GRPO OPD
监督来源 规则、验证器或奖励模型 冻结教师的 token 分布
信号粒度 常见为整段回答一个奖励 每个前缀上的词表分布
是否需要多回答成组比较 通常需要 不必
是否需要强教师在线前向 不一定 需要
能否发现超越教师的新策略 奖励允许时可以 通常受教师分布约束

GRPO 像只看考试总分，允许学生用老师没见过的方法解题；OPD 像老师每一步都在旁边纠正，反馈密集稳定，却也更容易把教师的风格和边界一并继承。

OPD 为什么可能比 RL 更省样本

假设一段推理有 2000 个 token。最终答案验证只给一个标量，所有步骤共同分享它；教师 logits 则在 2000 个位置都能提供分布差异。后者的监督密度高很多，通常具有更低方差。

但“更省样本”不一定等于“更省算力”。每条学生轨迹还要送入大教师做前向计算，完整词表 logits 的传输和存储也很昂贵。工程上常采用：

  • 只保留教师 top-k logits；
  • 分块计算 KL，避免保存完整 [batch, seq, vocab] 张量；
  • 教师与学生流水线并行或异步运行；
  • 预计算部分教师分数，形成近似离线 OPD；
  • 混合短阶段 off-policy SFT 与后续 OPD。

一个实际限制：tokenizer 最好一致

教师要对学生下一 token 的同一词表提供概率。如果两者 tokenizer 不同，“一个 token 对另一个 token”就无法直接对齐。例如教师的一个中文词可能在学生词表中被拆成三个 token。

可以设计字符、字节或字符串级映射，但会增加误差和复杂度。因此标准 OPD 最适合同一模型家族、共享 tokenizer 的强教师与弱学生，这也是 Qwen3 强到弱蒸馏很自然的原因。

OPD 什么时候可能失败

  • 教师与学生思维模式不兼容：教师习惯长推理，学生只会短回答，局部分布可能差得太远；
  • 教师没有新能力：教师虽然参数更大，但在学生访问的状态上给不出不同且可学的建议；
  • 学生走进不可恢复前缀：局部正确无法修复早期路线错误；
  • 反向 KL 导致模式收缩：学生过度集中于少数教师高概率 token，生成多样性下降；
  • 教师偏差被完整继承：OPD 模仿的是教师分布，不是客观真理；
  • 在线教师吞吐昂贵：训练速度可能受教师推理服务限制。

2026 年的 Rethinking On-Policy Distillation 强调，教师更大或榜单更强并不足以保证 OPD 成功，关键是教师能否在学生实际访问的状态上提供可利用的新信号。

一次推荐的训练流水线

对于一个明显弱于教师的学生，常见思路是：

  1. 先用教师生成的高质量轨迹做 SFT，建立基本任务格式和思维模式；
  2. 再让学生 on-policy 生成，暴露它自己的状态分布；
  3. 教师在学生前缀上给 top-k logits 或完整分布；
  4. 最小化选定的 KL/JSD 蒸馏损失；
  5. 用任务准确率、pass@k、生成熵和教师—学生 KL 联合评测；
  6. 必要时与可验证奖励 RL 混合，避免只能模仿教师。

这正是“先把学生带到老师附近，再在学生自己会走到的路上纠偏”的思路。

用一句话总结

OPD 就是：学生先生成自己的前缀，教师再在这些学生真实访问的状态上提供逐 token 概率监督，学生通过 KL 等损失向教师靠近。

它用密集监督缓解 SFT 的状态分布错位和 RL 的稀疏奖励问题，但代价是在线教师计算、词表对齐，以及能力上限对教师的依赖。
