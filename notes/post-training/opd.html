OPD：让老师指导学生自己的解题过程 ​

看懂老师的标准解法，和自己解题时不走偏，是两回事。模型也一样：只学习教师答案，训练时看到的前文可能与它实际生成的前文不同。

OPD 这里指 On-Policy Distillation（在线策略蒸馏）：学生先生成，教师在学生走到的上下文上提供反馈。 “On-policy”指样本来自学生当前策略，而不是部署后实时与用户聊天。OPD / GKD 原始研究

OPD 是一类训练方法，并没有唯一损失。下面选一种常见的 reverse KL 蒸馏，把完整分布计算与采样实现分别讲清楚。

前半部分介绍训练阶段 OPD；第 7 节起深入推理时蒸馏及截至 2026 年 10 月的研究进展，区分冻结模型的上下文迁移与测试时参数更新。

0. 完整损失与采样代理的组件对照 ​

固定本轮学生生成的回答：批大小为 B，回答 yb∼pold(⋅∣xb)，长度为 Tb，前文 hb,t=(xb,yb,<t)。有效回答 token 总数 N=∑bTb>0，本文采用全批有效 token 平均。

能获取教师完整词表分布时，直接最小化：

LOPD,full(θ)=1N∑b=1B∑t=1Tb∑v∈Vpθ(v∣hb,t)⋅log⁡pθ(v∣hb,t)qψ(v∣hb,t).

这是固定学生前文上的完整 reverse KL。若只有教师对已采样 token 的 log 概率，本文使用即时反馈的采样代理：

LOPD,sample(θ)=−1N∑b=1B∑t=1Tbpθ(yb,t∣hb,t)pold(yb,t∣hb,t)⋅sg[log⁡qψ(yb,t∣hb,t)pold(yb,t∣hb,t)].

两式是不同计算路径，不应默认相加。第一式直接求局部 KL；第二式构造可反传的策略代理，其损失数值不是 KL 数值。

公式组件含义在训练中的作用
hb,t学生自己生成的前文在学生实际走到的上下文训练，本轮作为固定输入
pθ当前学生的下一 token 分布待训练对象，参与反传
qψ冻结教师在同一前文的分布提供软目标或采样 token 概率反馈
∑v∈V遍历共同词表完整分布路径比较所有下一 token 选择
pθlog⁡(pθ/qψ)学生概率加权的 log 比值学生更可能选的 token 对 reverse KL 影响更大
pθ(yb,t)/pold(yb,t)当前学生与旧采样学生的概率比为采样代理提供关于当前参数的梯度通道
log⁡(qψ/pold)教师相对学生的即时反馈教师更支持该选择时为正，反之为负
sg停止梯度固定本轮反馈，不通过反馈内的概率再次反传
1/N 与有效位置求和有效回答 token 平均排除问题与 padding，明确长度权重

在 θ=θold 时，第二式的期望梯度与固定前文的局部 reverse KL 梯度一致，有限样本仍有误差。学生改变后，冻结的旧反馈通常不再给出当前局部 KL 的精确梯度，概率比也不会自动补齐该差异。两条路径均需刷新学生轨迹；即时反馈未完整计入前文变化对未来步骤的影响。即时 token 反馈实现

本文假设词表对齐、温度为 1，并在学生有正概率的位置能取得教师有限的 log 概率。教师零概率、分词不一致或仅提供截断 top-k 分布时，需要额外处理，不能原样代入完整词表公式。下文拆解局部 KL、反馈、梯度和训练流程。

1. 学习发生在什么地方？ ​

设问题为 x，学生本轮采样出的回答是 y，第 t 步前文为：

ht=(x,y<t)

在同一个前文上，学生与教师分别给出下一 token 分布：

pθ(v∣ht),qψ(v∣ht)

θ 是学生参数，ψ 是教师参数，v 遍历词表 V。下面假设词表已对齐、温度为 1，教师冻结。

例如，学生写到“先把所有数字相加”。教师不是另开一道题，展示自己完整的标准解法，而是在这段学生前文上计算下一 token 概率。它提供的是数值反馈，不必生成一句自然语言批语。实现说明

2. 核心公式：让学生分布靠近教师 ​

在一个固定前文 ht 上，reverse KL 是：

Kt(θ)=DKL(pθ(⋅∣ht)∥qψ(⋅∣ht))

展开为：

Kt(θ)=∑v∈Vpθ(v∣ht)log⁡pθ(v∣ht)qψ(v∣ht)

它包含三件事：

  • pθ 的权重： 学生更可能选的 token，对损失影响更大。
  • log⁡pθ−log⁡qψ： 衡量学生是否比教师更偏向这个选择。
  • 词表求和： 不是只看已生成文字，而是比较整个下一 token 分布。

把一批学生生成的前文固定下来，可以直接计算局部蒸馏损失：

Lfull(θ)=Eh∼doldDKL(pθ(⋅∣h)∥qψ(⋅∣h))

dold 表示本轮学生生成的前文分布，计算时对批次中的有效回答 token 取平均；pold 是采样版本。每轮刷新学生回答，再在这些固定前文上求梯度；不对离散生成过程直接反传。这类学生生成数据上的分布匹配，是 OPD 的基本训练构造。GKD 算法说明

用两种选择算一下 ​

假设某个位置只考虑两个 token，学生与教师分布是：

p=(0.8,0.2),q=(0.2,0.8)

那么：

K=0.8log⁡4+0.2log⁡(1/4)≈0.832

学生太偏向教师不支持的第一个 token。若学生改成 p=(0.5,0.5)，损失降为约 0.223；当 p=q，损失为 0。

这是一个固定前文的教学例子，解释了“靠近”怎样变成数值目标。它衡量教师与学生的一致性，不直接衡量答案是否客观正确。

3. 只有教师对已采样 token 的概率，怎么办？ ​

有些接口不给完整词表分布，只能算教师对学生已生成 token 的 log 概率。利用期望形式：

Kt=Ev∼pθ(⋅∣ht)[log⁡pθ(v∣ht)−log⁡qψ(v∣ht)]

于是，对学生采样的 yt，可以计算一个反馈：

gt=log⁡qψ(yt∣ht)−log⁡pold(yt∣ht)

它是负的采样 log 概率比，常作为逐 token 的优势信号。Thinking Machines 的采样实现

设学生给某个 token 的概率为 0.1，教师给 0.4，则 gt=log⁡4>0，倾向于鼓励它；交换两者，gt=−log⁡4<0，倾向于抑制它。

单个 gt 可正可负。 这不与 KL 非负矛盾：在对应的学生分布下，E[gt]=−Kt≤0，KL 是对所有选择的平均。

4. 反馈怎么变成可反传的损失？ ​

仅把固定样本上的“学生 log 概率减教师 log 概率”求平均，再直接反传，并不能自动得到正确的 reverse KL 采样梯度。原因是：抽到哪个 token，也取决于学生概率。

对固定前文，求导可得到：

∇θKt=Ev∼pθ[(log⁡pθ(v)−log⁡qψ(v))∇θlog⁡pθ(v)]

式中省略了共同的条件 ht。求导过程中多出的 1 项会因 ∑vpθ(v)=1 而抵消。

这就能构造一个策略梯度风格的采样损失。先定义概率比：

ρt(θ)=pθ(yt∣ht)pold(yt∣ht)

再最小化：

Lsample(θ)=−Et[ρt(θ)sg(gt)]

sg 是 stop-gradient。旧概率、教师概率和本轮 gt 都作为固定反馈，只通过当前学生概率反传。Et 是对有效回答 token 的平均。

在 θ=θold 时，ρt=1；但它对 θ 的导数不为零，因此仍能产生训练梯度。把 ρt 当常数 1 丢掉，就把这条更新通道也丢掉了。

这是与 Thinking Machines 所用即时 token 反馈相对应的一种 importance-sampling 写法。它给出固定前文上的局部 KL 更新；前面 token 改变后续前文的长期影响没有在这条即时反馈中完整计算。多轮复用数据时，旧前文分布与当前学生也会产生差异，应刷新样本，或采用相应的修正与稳定化设置。实现及其即时反馈设定

5. 它与 SFT 的差异藏在公式哪里？ ​

SFT 的单位置目标是：

ℓSFT=−log⁡pθ(yt∗∣x,y<t∗)

这里的 y∗ 是示范，目标是特定的标准 token，前文也是示范前文。

本篇的 OPD 则使用学生前文上的：

DKL(pθ∥qψ)

所以差异有两个维度：前文由谁生成，以及学习目标是单个示范 token 还是教师分布反馈。

也可以在学生前文上使用 forward KL 或其他分布损失；它们仍可属于 OPD。“学生自己采样”与“选择 reverse KL”是两个独立的设计选择。GKD 的损失选择

6. 从公式搭出一轮 OPD ​

OPD 的密集反馈来自教师对下一 token 的判断，未必能精确指出每个推理错误。它需要教师计算、学生采样以及分词对齐，但其训练对象很清楚：学生实际会走到的上下文，和这些地方的生成选择。

进一步把多个领域教师的能力整合到同一个学生，见 MOPD 多教师在线策略蒸馏与 MiMo V2。

7. Inference time distillation 与 OPD 的关系 ​

研究更新截至 2026 年 10 月 7 日。 Inference-time distillation（推理时蒸馏）目前并不是一个具有唯一目标函数的算法名称。阅读论文时，首先要看知识写入哪里，以及测试阶段是否更新参数。

路线推理时改变什么与本文前面的 OPD 的关系
训练阶段 OPD部署前更新学生参数学生轨迹上的教师监督是核心
In-context distillation检索示范、上下文与教师调用路由可冻结模型，通常没有 KL 损失或反向传播
Test-time self-distillation当前任务中的模型参数或适配器将学生采样、反馈与蒸馏更新移到测试阶段
持续在线蒸馏在任务流之间保留学习状态需要说明跨任务迁移、更新顺序与遗忘
Context distillation into fast weights在线更新记忆模块的快速权重可以是表示匹配，与 token 级 OPD 不同

因此，“on-policy”描述生成数据与学习策略的关系，“inference-time”描述知识转移发生的阶段。两者不是互斥标签，也不是同义词。长思维链、多次采样或检索本身，都不能证明模型在推理时进行了参数蒸馏。

8. 冻结模型的推理时蒸馏 ​

教师示范检索与学生教师级联 ​

直接以 Inference-Time Distillation 为题的研究，使用的是动态 in-context learning 与 self-consistency cascades。论文于 2025 年 12 月首次公开，2026 年 4 月修订；它不需要微调学生权重。

先让较强教师执行少量任务，保存带观察、推理和动作的示范。学生执行新任务时，在每一步检索相关示范作为上下文，再生成若干候选动作。候选一致时执行学生动作；不一致时调用教师。行为改变来自上下文和路由，而不是参数更新。论文最新版本

用简化记号表示这条执行链：

Ct=Retrieve(Dteacher,ht),at(1:n)∼pθ(⋅∣ht,Ct)at={at(1),候选动作通过一致性检查Teacher(ht),否则θ 保持固定

这可以使用仅提供生成接口的模型。示范库与每步检索提供了知识转移，一致性检查决定何时回退；它不对应前文的 DKL(pθ∥qψ) 训练目标。

论文最新摘要报告：ALFWorld 上达到教师准确率、每回合成本约降低 2.5 倍；AppWorld 上约降低 3.5 倍成本，同时保留约 79% 的教师准确率。后一个结果不是同准确率下的 3.5 倍降本。 示范收集还有前置成本，数字取决于论文的模型、价格和任务设置，不能直接当作当前 API 报价。

为什么它值得关注 ​

这个方向把“把教师能力搬到小模型”转化为部署系统的设计问题：选择哪些经验、何时检索、何时升级到教师。适合快速迭代、无法访问权重或不希望每次重新训练的 Agent 系统。

但多个样本可能一致地犯错，教师也可能出错。检索文本增加输入 token，重复采样和回退增加调用次数，所以只统计学生模型大小会低估成本。离开示范库、改变领域或改变工具接口后，收益也需要重新验证。

9. 测试时更新参数的 SDPO ​

2026 年 1 月的 Reinforcement Learning via Self-Distillation 提出 SDPO（Self-Distillation Policy Optimization）。它利用同一个模型在看到反馈后更善于判断原先尝试的能力，形成“自教师”。

设学生先回答 y∼pθ(⋅∣x)，环境返回反馈 f，如运行错误、失败测试信息或已验证的成功尝试。相同的模型有两个角色：

pt=pθ(⋅∣x,y<t)qt=sg[pθ(⋅∣x,f,y<t)]

论文的基本蒸馏目标为：

LSDPO=∑tDKL(pt∥qt)

教师的优势来自新增反馈，而不必来自更大的外部模型。 教师在学生原来的前文上重新计算概率，不必另生成一份修正答案；教师分支停止梯度。这个 KL 方向与前面的 reverse KL 一致，但教师条件发生了变化。SDPO 方法与测试时实验

SDPO 也可以用于普通训练阶段；它的测试时实验则针对一题反复尝试、取得反馈并更新模型。它把交互历史影响逐步压入权重，后续尝试不必把全部历史继续放进上下文。这比仅追加错误信息的多轮对话多了一条参数学习通道。

论文在筛选出的 LiveCodeBench 困难子集上报告，到达约 22% 的解发现概率时，最难组所需生成次数约为 best-of-k 或多轮采样的三分之一。该实验涉及 9 道极难题、19 道难题及特定筛选条件。生成次数减少不等于总耗时或 GPU 成本减少三倍，教师前向、反向传播和测试执行都应计入。

该路线仍需要有信息量的反馈。只有“失败”且一直没有成功样本时，不能假设模型能凭空得到足够的纠错信息；测试环境能提供什么，是算法能否工作的关键条件。

10. 2026 年近期前沿进展 ​

TTPO 从真实答案转向无标签共识 ​

2026 年 8 月的 TTPO（Test-Time Policy Optimization）研究没有标准答案的测试时训练。它先对同一问题采样多条回答，以出现最多的答案构造伪标签，再把轨迹分成两组：

  • 与伪标签一致的轨迹：采用答案条件自教师的蒸馏监督，并选择性加权 token。
  • 与伪标签不一致的轨迹：采用组式 RL 的负向信号，并选择性约束 token。

论文使用的正样本蒸馏是 forward KL，不能直接把它代入前面的 reverse-KL 采样公式。整体可以概括为：

LTTPO=LOPSD,positive+λRLLRL,negative

这只是两条学习分支的结构表达；具体权重与 mask 由论文定义。核心是减少错误伪标签对所有轨迹的统一污染，而不是宣称多数票一定正确。TTPO 方法

作者报告，在 AIME26、HMMT26 与 BRUMO25 三个测试集直接进行无标签适应时，Qwen3-1.7B 的平均成绩从 38.0 提升至 45.2，即增加 7.2 个百分点。这里是对测试输入进行适应后的评估，不能与完全不接触测试输入的冻结模型训练结果混为一谈。其负样本判断依据也是实验中的统计规律：与多数答案不同的少数答案仍可能恰好正确。

ASCENT 从单题适应转向跨任务经验积累 ​

2026 年 10 月 4 日公开的 ASCENT，研究长程 Agent 的在线测试时训练。每个任务只尝试一次，完成后由环境验证；成功轨迹提供事后信息，失败则跳过这次更新。初始模型的冻结副本作为教师，学生携带跨任务保留的 LoRA 适配器。

把学生前文记为 c，已验证经验记为 zi，可以将论文目标简写为：

qi=sg[pθ0(⋅∣zi,c)],piϕ=pθ0,ϕ(⋅∣c)Li(ϕ)=∑有效位置αi,t,jDKL(qi∥piϕ)

这是 forward KL 的完整分布匹配。基础权重 θ0 冻结，更新 ϕ 并带到下一个任务。教师读取经过过滤的成功经验，但训练位置仍来自学生实际的尝试；它不等于直接模仿成功轨迹里的每个 token。ASCENT 方法

论文在 ALFWorld 与 WebShop、两个模型规模上报告任务流表现和留出场景迁移收益。它最值得关注的是把“记住文本经验”变成“在参数中持续吸收经验”，并用固定教师与验证门控控制漂移。

这篇工作刚公开，当前证据主要是作者的任务流实验。成功筛选不能识别所有无用步骤；初期几乎没有成功时，学习信号也会不足。跨任务状态保留意味着评估顺序、适配器重置方式和测试流组成都必须明确。

TTCD 将长上下文知识写入快速权重 ​

2026 年 8 月的 TTCD（Test-Time Context Distillation）用长窗口教师指导短窗口学生，以隐藏状态差异训练快速权重，让有限记忆保留对后续预测有用的信息。TTCD 论文

这是另一种推理时知识压缩：主要处理上下文与记忆，而不是依据数学答案或工具成功率构造策略优势。它依赖配套的训练与架构设计，不能当作任意部署模型都能直接开启的 OPD 开关。

11. 前沿研究对蒸馏收益的反思 ​

更高准确率不一定意味着更大的能力边界 ​

2026 年 8 月的研究从 test-time scaling 角度检查训练阶段 OPD：在作者测试的模型与任务中，OPD 后的平均采样准确率更高，但采样预算很大时，蒸馏前模型的 pass@K 可能更好。这提示一种解释：训练可能让已有正确路径更容易被采到，同时降低路径多样性。OPD 与 test-time scaling 分析

这是对训练阶段 OPD 的分析，不是对所有测试时蒸馏路线的直接否定。它提示需要同时报告：

  • 单次或平均采样准确率，衡量稳定输出的能力。
  • pass@K，衡量固定模型的多次样本中至少有一个正确答案的概率；它不自动说明系统能选出那个答案。
  • discovery@K，衡量允许反馈和更新的顺序尝试中，在预算内发现正确解的概率。
  • 留出任务收益，检查学到的是当前题目、某个测试集合，还是可迁移技能。

教师看到更多信息也可能伤害推理 ​

2026 年 7 月的研究发现，对部分 thinking models，向自教师提供额外答案等特权信息，会降低长推理预算下的表现。作者将问题与分叉、验证和自我修正位置的监督变化联系起来。Rethinking On-Policy Self-Distillation

因此，需要看教师信息是否真的帮助学生学习，而不只是让教师更容易判断终点。特别要检查它是否过度惩罚试探、回溯和纠错步骤。该结论来自特定模型与数学任务，不能推广成“额外反馈都无用”。

12. 如何判断一种推理时蒸馏是否值得使用 ​

最先确认的是部署时实际可获得的监督：教师示范、教师概率、运行反馈、验证器还是模型自己的共识。只有训练数据中才有的正确答案，不应未经说明地出现在测试时教师上下文中；环境真实返回的结果与离线标准答案也应分别记录。

其次明确学习状态的寿命：当前问题结束后重置，还是为用户、会话或整条任务流保留？持续适配可能带来迁移，也可能带来顺序依赖与遗忘。论文若在测试输入上更新参数，应注明这种适应协议，再与同协议的基线比较。

最后按完整预算核算。一个方便审计的成本表达是：

Ctotal=Csetup+∑i(Crollout,i+Cteacher,i+Cupdate,i+Cverify,i+Cretrieve,i)

示范生成属于前置成本，长检索上下文计入模型推理，教师概率前向与梯度更新也不是免费操作。还应分别报告首个答案延迟、GPU 时间、生成 token 和 API 成本，不能用生成次数替代所有指标。

当前值得优先跟踪的方向是：用可获得的反馈构造更可靠的自教师，选择性蒸馏关键位置，并在有成本与稳定性约束的条件下保留跨任务经验。 冻结模型的检索级联更接近可直接落地的系统方案；参数自蒸馏更接近研究前沿，尤其需要反馈质量、评估协议和持续学习稳定性的证据。

推理时蒸馏研究资料 ​

  • Inference-Time Distillation 最新版本：冻结模型、教师示范检索与一致性级联。
  • Reinforcement Learning via Self-Distillation：SDPO，尤其 §5 的单题测试时适应。
  • TTPO：无标签测试时自蒸馏与非对称 RL 分支。
