RLVR：用可验证结果训练推理能力 ​

假设要教模型做数学题。SFT 的做法是提供标准解法，让模型模仿；RLVR 的做法是让模型先自己解，再检查答案，利用得分调整模型。

RLVR（Reinforcement Learning with Verifiable Rewards）强调奖励来自可验证的结果。 它描述的是奖励来源，可以搭配 PPO、GRPO 等不同优化算法。Tülu 3 用这个名称介绍数学和可检查指令遵循任务上的训练。Tülu 3 技术说明

1. 一轮训练到底做什么？ ​

输入不仅需要问题 x，还需要可靠的判分依据 z，例如参考答案、隐藏测试或约束配置。z 供训练系统判分，通常不直接作为学生生成时的输入。

对每题生成 G 个回答：

yi∼πold(⋅∣x),i=1,…,G.

πold 是本轮采样模型的快照。模型生成时仍按 token 逐个采样，并不知道哪一份会通过验证。

2. 第一层公式：奖励是怎样计算的？ ​

最简单的数学答案匹配奖励是：

r(x,y;z)={1,Verify(Extract(y),z)=true,0,否则.
组件具体做什么
Extract从模型回答中抽取最终答案，避免把整段推理直接当答案
Verify检查等价性、测试结果或约束是否满足
z参考答案、测试集或任务约束
r优化器接收的数值反馈

例如，“1/2”和“0.5”可能等价，不能只靠字符串相同判分。代码题可以采用“全部测试通过才得 1”，也可以用测试通过比例作为部分奖励；这是两种奖励设计，不能混为一个固定定义。

DeepSeek-R1-Zero 使用规则式准确性奖励，数学题检查最终答案，代码题检查测试；还设置格式奖励。DeepSeek-R1 报告

格式正确和答案正确应分别记录。 如果只要写出指定标签就得高分，模型可能学会排版，却没有学会解题。验证器也不会因为自己是程序就天然可靠：解析错误、测试覆盖不足，都会变成错误的训练信号。

3. 第二层公式：奖励怎么让模型学习？ ​

先看不带裁剪与 KL 的基本目标：

J(θ)=ExEy∼πθ(⋅∣x)[r(x,y;z)].

意思是：让模型自己生成的回答，平均得到更高奖励。问题在于，答案匹配与运行测试通常不可微，不能把“测试通过”直接反向传播进 Transformer。

策略梯度绕过了这个问题：

∇θJ=E[(r−b(x))∑t=1T∇θlog⁡πθ(yt∣x,y<t)].

这里假设判分规则固定，不依赖待训练参数。b(x) 是与当前采样动作无关的基线，用来降低估计方差。这个公式先解释通用策略梯度；后面的 GRPO 使用同组相对优势，并不是把同组均值当作严格独立的基线来推导。

把公式读成一句话：高于基线的回答，让它用过的 token 选择更容易出现；低于基线的回答，让这些选择的整体倾向下降。

这是一种统计更新。它并不知道某段推理具体错在哪里，也不会保证高奖励回答中每一步都正确。多个回答共享前文，参数又相互耦合，实际更新也不是机械地给每个字独立加减概率。

4. 第三层公式：用 GRPO 组织一次实际更新 ​

下面选择常见的组内标准化版本作教学。不同工程实现会调整归一化、长度权重和 KL 配置，RLVR 本身并不规定这些细节。GRPO 的原始算法来自 DeepSeekMath。

先把奖励转换为优势：

r¯=1G∑iri,σr=1G∑i(ri−r¯)2,Ai=ri−r¯σr+εnum.

Ai>0 表示比组内平均更好；Ai<0 表示更差。数值稳定项 εnum 防止除零。一般把本轮 Ai 当成固定值，不对验证器和优势计算反传。

再计算已生成 token 的新旧概率比：

ρi,t(θ)=πθ(yi,t∣x,yi,<t)πold(yi,t∣x,yi,<t).

一份回答的主体损失可以写成：

Li=−1Ti∑t=1Timin(ρi,tAi, clip(ρi,t,1−δ,1+δ)Ai)+βTi∑t=1TiDKL(πθ(⋅∣hi,t)∥πref(⋅∣hi,t)),

其中 hi,t=(x,yi,<t)，批内再平均各题、各回答的损失。

组件为什么需要它
Ai指定鼓励还是抑制，以及信号强度
ρi,t比较训练中的模型与实际采样模型
clip 与 δ限制代理目标对过大概率变化的激励，不是直接锁住参数
前面的负号训练器最小化损失，而策略目标需要最大化
πref 与 β可选 KL 约束，控制模型偏离固定参考策略的程度
1/Ti此处采用每份回答的 token 平均，排除问题和 padding

旧策略和参考策略不是同一个角色。 旧策略跟着采样轮次更新；参考策略通常固定。KL 约束也不是验证奖励：即使验证得分相同，它仍可能产生梯度。完整 KL 可以直接计算，也有采样近似，不能把两者的单样本数值视为相同。

5. 手算一个例子：四份解答，只有一份正确 ​

题目是“3x+2=11，求 x”。四次采样分别回答 2,3,4,5，奖励为：

r=[0,1,0,0],r¯=0.25,σr=0.1875≈0.433.

忽略很小的稳定项：

A≈[−0.577, 1.732, −0.577, −0.577].

正确回答得到正优势。假设它某个 token 的旧概率为 0.20，更新中变成 0.26，则 ρ=1.30。取 δ=0.20：

min(1.30×1.732, 1.20×1.732)≈2.078.

这个 token 的策略损失贡献是 −2.078，先忽略长度平均和 KL。裁剪让模型继续把该概率增大时，不再从这一正优势项获得更多收益。

假如四份答案都错，奖励全为 0，组内优势也全为 0。这题的奖励驱动策略项没有学习信号；KL 等其他项仍可能更新参数。此时需要改善采样、选题难度或反馈，而不是期待归一化凭空告诉模型正确解法。

6. 什么时候适合用，什么时候不够用？ ​

数学、代码、格式与约束遵循适合 RLVR，因为结果通常能检查。创意写作、解释是否清晰、多目标开放任务难以压缩成可靠的对错验证，需要其他反馈方式。

主要限制有三个：稀疏奖励使全错样本难以学习；结果对不代表过程对；模型可能利用验证器漏洞。实践中应单独检查真实任务表现、测试覆盖、解析失败和奖励分布，不能只盯训练奖励上涨。

如果希望利用“哪个测试失败、为什么失败”的文本，继续阅读 SDPO。如果希望把开放任务的要求拆成多项评分标准，阅读 Rubric-based OPD。更详细的优化推导见 GRPO 和 PPO。
