SDPO：把反馈变成自我蒸馏信号 ​

模型写了一段代码，测试失败。只告诉它“得 0 分”，和告诉它“输入为空时，你的代码访问了不存在的第一个元素”，信息量很不一样。

SDPO（Self-Distillation Policy Optimization）让看过反馈的模型充当自教师，指导没有反馈的学生模型。 本文对应《Reinforcement Learning via Self-Distillation》，不是其他同名缩写算法。原始论文

先把这个容易混淆的点说清楚：基础方法中的教师与学生可以使用同一套当前参数；区别是教师多看了反馈。教师分支在本次更新中停止梯度。

1. 关键区别：不是重新生成正确答案再做 SFT ​

设问题为 x，学生原回答为 y，反馈为 f。在相同的原回答前缀 y<t 上比较：

pθ,t(v)=πθ(v∣x,y<t),qt(v)=sg[πθ(v∣x,f,y<t)].

v 是候选下一 token，sg 表示停止梯度。实际实现会按模板把问题、反馈与原回答拼接，而不是直接增加一个抽象参数。

原回答已经生成完，随后获得的反馈可以用来复评较早的位置。这是训练时的事后指导，生成学生答案时并没有提前看到反馈。复评时也不会把前面已经发生的错误偷偷替换成正确前文。

2. 核心损失：同一前文，两种信息条件 ​

对本轮固定的学生轨迹，本文采用有效回答 token 平均：

LSDPO(θ)=1N∑i,tDKL(pθ,i,t∥qi,t)

N 是所有有效回答 token 的数量。展开某个位置的 KL：

Kt=∑v∈Vpθ,t(v)log⁡pθ,t(v)qt(v).

这里采用论文核心定义中的 reverse KL：学生在前，教师在后。方向反过来是另一个目标；具体实现也可以选择其他散度。

公式部分怎么理解
pθ,t(v)没看反馈时，学生有多想选这个 token
qt(v)看过反馈后，自教师认为它有多合理
log⁡(p/q)两种条件下对该选择的意见差异
词表求和在这个位置比较所有候选，而不只比较实际生成的那个
sg本轮只移动学生分布，教师目标不参与反传
固定 y<t在学生实际经历的前文上指导它

为什么要停止教师梯度？如果两边同时被这个损失推动，可能出现教师主动向学生靠近，而不是学生吸收反馈。停止梯度固定的是本次目标，不是永远冻结同一套参数：共享参数的学生更新后，下轮自教师也会改变。论文方法与实现说明

3. 从 KL 拆出“每个选择的优势” ​

定义某位置某候选的反馈：

At(v)=log⁡qt(v)pθ,t(v).

若 qt(v)>pθ,t(v)，反馈为正；反之为负。它比较的是教师相对于学生的支持程度，不是答案是否正确的直接证明。

对固定前文和固定教师，梯度为：

∇θKt=∑v∇θpθ,t(v)(log⁡pθ,t(v)qt(v)+1)=−∑vpθ,t(v)At(v)∇θlog⁡pθ,t(v).

第二步用到了 ∑v∇θpθ,t(v)=0，因为分布总和恒为 1。概率权重 pθ,t(v) 不能漏掉：它使求和对应学生分布下的期望。

这和策略梯度的形状相似。GRPO 用整段回答的相对奖励作优势；这里每个位置、每个候选都可以有不同的 At(v)。因此，“最终全错”也可能有学习信号：只要反馈改变了自教师分布，KL 就可能非零。

这个推导是固定轨迹上的局部蒸馏梯度。没有对离散采样、验证器或反馈文本求导，也没有把未来所有状态变化完整纳入梯度。不能将它误读为整个交互过程的精确全局梯度。

4. 数值例子：空列表应该返回什么？ ​

任务是返回列表最大值，空列表返回 None。学生原代码在空列表上报错。反馈指出：“空列表不能访问第一个元素，应先处理空输入。”

为便于手算，把一个相关位置简化为三个候选 token。下表是教学用概率，真实词表远大于三个，真实代码含义也需要多个 token 才能表达。

候选学生 p反馈教师 qA=log⁡(q/p)
None0.200.701.253
00.500.20-0.916
-10.300.10-1.099

该位置的 KL 为：

Kt=0.2log⁡(0.2/0.7)+0.5log⁡(0.5/0.2)+0.3log⁡(0.3/0.1)≈−0.251+0.458+0.330=0.537.

单个候选的贡献可以为负，但完整 KL 非负。继续看 softmax 前的学生 logit zv：

∂Kt∂zv=pv(log⁡pvqv−Kt).

代入得到约 [−0.358, 0.190, 0.169]。梯度下降减去梯度，所以 None 的 logit 上升，另两个下降。这个例子里，模型朝反馈指出的方向移动。

如果错误已经在前文中发生，自教师并不一定能直接“修掉过去”。它只能在固定错误前文的后续分布上提供指导；较早位置则通过各自的复评获得信号。

5. 为什么同一个模型也能教自己？ ​

同一个人闭卷做题，与看完错题提示再复盘，判断能力可能不同。SDPO 利用的就是这种信息条件差异，不是凭空创造一个更强的老师。

反馈可以是运行错误、失败测试等文本；在只有对错奖励时，也可以利用同组成功回答作为额外上下文。若同组全错，又没有有用反馈，自教师可能仍不知道正确方向。论文还研究了教师正则化与 EMA 等稳定方案；这些是实现选择，不是基础定义的必需组件。原始研究

EMA 教师可以按下式缓慢跟随学生：

θteacher←(1−α)θteacher+αθ.

α 越小，教师更新越慢；代价是需要维护额外参数。若用 top-k 分布节省显存，应妥善处理词表尾部概率，不能直接截掉尾部再声称算出了完整 KL。官方实现

6. 如何构建训练程序？ ​

text
采样当前学生回答，并取得环境反馈
把回答 token 与有效位置 mask 保存下来
无反馈上下文：计算可反传的学生 log 概率
有反馈上下文：在 no_grad 中复评同一回答前缀
逐位置计算分布散度，屏蔽问题与 padding
反传学生分支，更新参数
刷新回答和反馈，进入下一轮

这是单轮刷新、固定轨迹的基础教学版本。反复复用旧轨迹时，数据逐渐不再来自当前学生；不能无条件称为严格 on-policy。实际工程要明确旧概率、重要性修正、裁剪和刷新频率。

还要注意两套上下文长度不同，但被比较的回答位置必须对齐；教师上下文更长，需要额外前向计算，也更消耗上下文窗口。无需生成修正答案，不等于无需教师计算。

7. 与 RLVR、OPD 和 SFT 的区别 ​

方法训练数据与目标
SFT通常在给定示范前文上，增加示范 token 概率
RLVR验证结果转成标量奖励，再进入策略优化
OPD学生生成轨迹，教师在这些前文上提供分布反馈
SDPO用反馈增强的自教师，把信息优势蒸馏到无反馈学生

SDPO 适合代码测试、工具调用等有丰富反馈的任务。反馈不可靠、提示诱导错误，或者模型看了反馈仍无法判断时，蒸馏也可能强化错误。应检查真实成功率、自教师反馈质量和 KL 变化，不能把“KL 降低”直接等同于“任务能力提高”。
