多头注意力：为什么要多头，和单头差在哪？ ​

“多头就是从多个角度看问题”，这句话好记，却没有回答最关键的三件事：每个角度怎么形成？多个结果怎么合并？代价是否翻倍？

我们先把单头算明白，再看多头究竟增加了什么。

1. 注意力不是挑一个词，而是加权读内容 ​

设输入是：

X∈RL×D

L 是序列长度，D 是隐藏宽度。先用三组可学习矩阵做投影：

Q=XWQ,K=XWK,V=XWV

可以这样理解：

  • Query： 当前 token 想找什么线索？
  • Key： 每个候选 token 用什么特征被找到？
  • Value： 真正被读走、传给当前位置的内容是什么？

这只是帮助理解的类比。Q,K,V 都是网络学出来的向量，不是人写好的关键词，也不代表三个独立语义标签。注意力定义

对查询位置 i，先给候选位置 j 打分：

sij=qi⊤kjdk+Mij

再沿候选位置做 softmax：

aij=esij∑u∈visible(i)esiu

最后取 value 的加权和：

oi=∑jaijvj

权重来自 Q,K，被混合的是 V。 把 attention weight 当成最终输出，或直接拿权重加权原始 token ID，都会把计算过程弄错。

2. 用三个位置算一次单头 ​

设某个查询与三个 key 的维度是 2：

q=[1,0],k1=[1,0],k2=[0,1],k3=[1,1]

不加 mask，缩放后的分数为：

s=[1/2,0,1/2]

softmax 后约为：

a=[0.401,0.198,0.401]

再设 value 是：

v1=[1,0],v2=[0,1],v3=[1,1]

输出约为：

o=0.401v1+0.198v2+0.401v3≈[0.802,0.599]

这是人为构造的教学数据。它说明注意力通常是软性混合，不是硬选最高分的一个位置。value 也不必与 key 相同；二者承担不同角色。

为什么要除以 dk？ ​

如果 q,k 的各维近似独立、零均值、单位方差，点积的方差会随 dk 增大。分数过大，softmax 容易变得接近 one-hot，很多方向的梯度会变小。

除以 dk 是控制分数尺度的一种设计。它不是把注意力权重归一化到和为 1；真正做这件事的是 softmax。缩放理由

这些统计假设用于解释尺度选择，不意味着实际训练后的 Q,K 永远服从独立标准分布。

3. 多头不是把同一次结果复制几份 ​

对第 h 个头，分别学习投影：

Qh=XWQ(h),Kh=XWK(h),Vh=XWV(h)Oh=softmax(QhKh⊤dh+M)Vh

拼接各头结果，再做输出投影：

MHA(X)=Concat(O1,…,OH)WO

H 是头数，典型标准 MHA 中 dh=D/H。每个头有自己的匹配方式和 value 表示，因此能形成不同的注意力分布。MultiheadAttention 官方说明

实现上常用一次大矩阵乘法得到 Q,K,V，再 reshape 成各头。这和上面分开写投影的数学结构一致。

“先投影再分头”很重要：每个头的特征可由整个输入向量的线性组合得到。 不是简单规定第一个头只能看到原始特征的前一段、第二个头只能看到后一段。

4. 多头真正多了什么表达能力？ ​

单头对一个查询位置，只产生一组候选位置权重 aij。这组权重用于该头 value 的各个通道。

多头则有：

aij(1),aij(2),…,aij(H)

因此不同特征子空间可以使用不同的位置混合方式。例如某个头更关注附近的词，另一个头更关注远处的实体线索，两类信息先分别保留，再由 WO 混合。

这个解释的重点是独立的注意力权重分布。它不保证每个头都会形成明确的“语法头”“指代头”，更不能拿一张热力图就断定因果作用。

为什么一只更宽的头不一定等价？ ​

标准单头如果覆盖 D 维，仍只有一组 softmax 权重。多头虽然每头更窄，却允许多组独立 softmax。因为 softmax 是非线性的，简单把投影拼大，再只做一次 softmax，通常不能复现所有多头的混合方式。

反过来，单头也能利用复杂的特征表示完成很多任务；多头并不是“每种语言关系必须分配一个头”的硬性要求。研究发现部分训练后的头可以被裁剪而性能变化有限，说明头之间可能有冗余。头冗余研究

5. 维度是怎么变的？ ​

用 B=2,L=8,D=512,H=8,dh=64：

阶段形状
输入2×8×512
大投影后的 Q,K,V各为 2×8×512
拆头并交换轴各为 2×8head×8seq×64
每头分数矩阵2×8head×8query×8key
每头输出2×8head×8seq×64
拼接并输出投影2×8×512

两个“8”分别是头数和序列长度，恰好一样，但含义不同。一般写为：

Q,K,V:B×H×L×dhA:B×H×Lquery×Lkey

softmax 沿 key 的位置维做，不沿头数做。各头不需要一起竞争“谁的权重更大”。

最终输出回到 D 维，才能与输入做残差相加。WO 可以混合不同头的通道；Concat 保留各头结果，并非直接把它们平均掉。

6. 多头是不是参数和计算都乘以 H？ ​

如果固定 D，令每头宽度 dh=D/H，忽略偏置，标准 MHA 的参数量是：

3HDdh+(Hdh)D=4D2

前三项来自各头的 Q,K,V 投影，最后一项来自输出投影。一只 D 维的标准单头也有约 4D2 个投影参数。

因此，在这个比较条件下，头数增加不等于投影参数乘以头数。但它会改变结构与实际运行开销。

注意力的核心乘法复杂度大致是：

O(BHL2dh)=O(BL2D)

而普通实现保存的注意力分数包含 BHL2 个元素。因此，固定宽度时核心乘法量相近，分数存储、softmax、调度和硬件效率仍可能变化。不能由一个复杂度式子就断言实际速度完全一样。

如果增加头数的同时保持每头宽度不变，D 也增大，参数与计算当然会增加。讨论“多头与单头谁更贵”必须先说明固定的是哪个维度。

7. Mask 和位置编码与多头是什么关系？ ​

多头回答“用几组匹配方式”，位置编码回答“如何让位置影响匹配”，mask 回答“哪些位置允许被读取”。它们可以组合使用：

  • 因果 mask 让所有头不能读取未来位置。
  • padding mask 排除补齐 token。
  • RoPE 可以分别旋转每头的 Q,K。
  • 相对偏置或 ALiBi 可以在分数上加入头相关的位置项。

mask 通常在 softmax 之前加入；否则已经混入不允许位置的信息。实现还应避免让一个查询行所有候选都被屏蔽，否则 softmax 可能出现无效数值。

不同接口对布尔 mask 的 True / False 含义可能不同，读代码要对照文档，不能直接复制约定。接口与 mask 说明

8. MQA、GQA 又为什么要共享头？ ​

标准 MHA 中，每个 query head 有自己的 key、value。自回归推理的 KV cache 因而要保存每层、每个 head 的历史 K,V。

MQA 让多个 query heads 共享一组 K,V；GQA 则按组共享。若 query 头数为 Hq，KV 头数为 Hkv：

1≤Hkv≤Hq

忽略其他缓存元数据，每层 KV 元素数量约为：

2BLHkvdh

前面的 2 对应 K 和 V。减少 Hkv 能减少缓存与访存需求，但不等于 query 也只剩一个头。GQA 在共享程度与表达能力之间做折中。GQA 论文

9. 把一次注意力计算走完 ​

如果只能带走一个判断标准，就看某个 query 是否拥有多组独立的注意力分布。它比“有很多并行向量”“能看多个词”更准确：单头本来就能同时读取多个位置。
